# Experiment 057 — self-delimiting variable-span K8

## Motivation

K7 removed fixed interaction arity but still found events by globally enumerating all non-overlapping subsets. That is an oracle-like combinatorial scheduler primitive and is poorly aligned with the CPU-first motivation.

K8 keeps variable interaction span while replacing global subset enumeration with a bounded sequential scan.

## Physical rule

For each possible start position, read non-overlapping width-`w` windows in physical order:

`p, p+w, p+2w, ...`

Maintain the XOR of encountered values. The candidate interaction ends at the **first nontrivial closure** with:

`XOR(prefix values) == 0`

and at least two windows.

Thus event arity is not chosen from a catalogue. It is the first content-determined closure length encountered along the ring.

The ring contains six windows' worth of capacity in the default comparison, so arity can range from 2 through 6 without a separate max-arity parameter.

For an enabled prefix, use one symmetric field:

`T = rotl(sum(values) mod 2^w, 1)`

and apply the same rewrite to every member:

`x' = (x + T) mod 2^w`.

No-op closures are skipped.

A stateless min/max scheduler compares only the at-most-one candidate generated by each start position.

## Equal-budget history assay

For each key width 4, 5, and 6, keep physical capacity fixed at six windows (`size = 6*w`).

Compare the same equal-budget histories used throughout the project:

- `A,A,A,B,B`
- `B,B,A,A,A`

with identical input multiset and event budget.

Eight deterministic backgrounds, both scheduler orientations, six write positions, and four complement-pair representatives give **384 comparisons per key width**.

## Result

### key width 4, size 24

- same full repertoire: 12
- seq1 strict superset: 49
- seq2 strict superset: 27
- incomparable reorganization: **296**
- different executable arity set: **351/384 = 91.4%**
- different future event trace: 353/384

### key width 5, size 30

- same: 74
- seq1 strict superset: 102
- seq2 strict superset: 69
- incomparable reorganization: **139**
- different executable arity set: **298/384 = 77.6%**
- different future event trace: 309/384

### key width 6, size 36

- same: 178
- seq1 strict superset: 95
- seq2 strict superset: 61
- incomparable reorganization: **50**
- different executable arity set: **184/384 = 47.9%**
- different future event trace: 200/384

All tested widths generate multiple interaction spans, including higher-order closures. Wider keys make closure rarer, so empty/small repertoires become more common, but the history dependence does not disappear.

## Why this is a cleaner substrate than K7

K7 asks an external scheduler to enumerate a combinatorial hyperedge catalogue and find matching subsets.

K8 asks only:

> starting here, how far does the current medium have to be scanned before the same fixed XOR closure condition is first satisfied?

The search is sequential and bounded by physical ring size. Arity is therefore a self-delimiting property of current content rather than a separately enumerated event type.

## Interpretation boundary

This still does not mean the substrate invented a relation language. XOR closure and the shared rewrite remain fixed microphysics.

The narrow result is:

> under one fixed sequential closure process, equal-budget history changes the span/cardinality and content of currently executable dependencies.

## Next audits

1. quantify the computational scaling improvement relative to K7 subset enumeration;
2. test whether a recurrent self-delimiting span is causally reusable across different histories;
3. ask whether history can make a useful closure **shorter under the same scan budget**, connecting directly to the earlier hypothesis that understanding is a reduction in the resource cost needed to expose a consequential distinction.
